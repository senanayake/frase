# Frase Spanish practice

A free, static Spanish practice app with conjugation drills, graduated hints, spaced review, guided voice exercises, a quest path and printable worksheets. It focuses on Mexican / Latin American Spanish. No account, paid API or backend is needed.

## Run locally

```sh
git clone https://github.com/senanayake/frase.git
cd frase
python3 -m http.server 8000 --directory dist
```

Open http://localhost:8000/ in your browser. Use a web server rather than opening the HTML file directly. No runtime packages need installing. Node.js 22 or newer runs the tests with `npm run check`.

## Publish your own website

1. Fork or copy this repository into your GitHub account.
2. Open **Settings > Pages**.
3. Under **Build and deployment > Source**, select **GitHub Actions**.
4. Open **Actions > Test and deploy Frase to GitHub Pages** and run the workflow, or push a commit to `main`.
5. Use the URL shown by the successful deployment. The expected URL for this repository is https://senanayake.github.io/frase/.

Subsequent pushes to `main` run tests before deployment. Pull requests run tests without publishing. Other static hosts can serve `dist/` directly; no backend or secrets are required.

## Move your progress to another website

Progress, personal packs and saved worksheets live in browser-local storage. They are not committed to this repository and do not automatically follow you to another domain, browser or device. In the old site, use **Settings > Export backup**. In the new site, use **Settings > Restore backup**. Restoring replaces that browser's notebook; export an existing notebook first if needed.

GitHub Pages publishes a public website. Each visitor has their own local notebook. Frase does not upload local answers. Speech uses a browser-provided service and availability varies; try Safari on iPhone if an embedded viewer blocks speech.

## Graduated hints

All exercise types use a shared three-step scaffold in `dist/js/hints.js`: locate the difference, recall a rule or see a masked fragment, then receive a minimal repair or partial word. An incorrect attempt never automatically reveals the complete model. Clear spelling and accent comparisons mark the exact character in a copy of the submitted response. Known verb forms distinguish tense/person mismatches from likely stem spelling slips. Missing words, extra words, articles, and order differences receive cautious comparison clues. Alternative wording is never certified incorrect solely because it differs from the answer key. Free production gets planning and rule clues rather than invented automatic corrections.

Lesson packs may supply an optional `hints` array of up to three strings. The exercise editor exposes three clue fields. Existing single `hint` fields and packs remain compatible. Attempt history adds optional `hintLevel` and `issueType` fields while retaining schemaVersion 1 and the existing storage key. The amount of help is recorded separately from whether the final response matches.

Research basis: Ferris & Roberts (2001), DOI 10.1016/S1060-3743(01)00039-X, supports indirect location feedback for self-editing in L2 writing. Lyster & Saito (2010), DOI 10.1017/S0272263109990520, supports corrective prompts in classroom language learning. These findings motivate the scaffold; they do not establish this exact three-step UI as optimal for long-term Spanish acquisition. No automatic competence judgments are inferred from a single repair.

## Upgrade content

The application engine is in `dist/js/engine.js`. UI and views are in `dist/js/app.js`. Versioned built-in content is in `dist/data/course.json`, generated by `scripts/build-content.py`. New tenses are data records; exercises declare a `type` and stable `id`. Keep existing exercise and tense IDs stable on updates. Do not change the `frase.learning.v1` storage key. Add migrations if the saved schema changes.

Add exercises directly in My lessons. Import a pack matching `dist/data/sample-lesson.json` to add a tense and exercises without a code change. Personal packs are namespaced by pack ID, so built-in IDs cannot be overwritten. Reimporting the same pack replaces its content and retains matching progress IDs. Backups include local progress, settings, and personal packs.

New interaction types require a new engine handler and UI rendering branch; existing content remains compatible. Automatic open-ended grading and cross-device cloud sync are separate future capabilities, not present in v1. DeepL and Conjugacion.es are external reference links, not integrated APIs.

## Development and verification

Run `python scripts/build-content.py` after editing the generator. Run `npm run check` for scheduling, answer checking, content, and pack validation. Serve the `dist` directory with any static web server. The GitHub Pages workflow tests the app and publishes this directory after pushes to `main`. Root hosting and project paths such as `/frase/` are supported.

## Learning and assessment

Checked answers use authored acceptable strings, punctuation normalization, and controlled subject omission. Accent differences request repair. The engine preserves ñ. Unmatched open phrasing is described as an answer-key mismatch, not a definitive grammatical error. Original production is explicitly self-assessed. A hint or repair is recorded as supported recall. Revealed answers are scheduled again soon. Independent recalls progress through 1, 3, 7, 14, and 30 days. Browser-local persistence is disclosed and exportable. No user answers are sent to a translation or AI service.

## Course scope

Built around the teacher's present, preterite, imperfect, simple future, present perfect, and ya notes. Latin American subjects are the default; vosotros is not included. Source answer-key errors are not copied. Compound perfect prompts explicitly request the target form rather than asserting one regional distribution as universal. The large prompt count includes variations across verbs, persons, and tenses; it does not imply 1,000 independent grammar lessons.

### Voice and mixed input (v1.2)

`dist/js/voice.js` wraps the browser's SpeechRecognition / webkitSpeechRecognition service. It requests `es-MX`, accepts final results only, and invalidates callbacks after cancellation so a late transcript cannot replace another exercise. Audio may be processed by the browser provider online. Frase has no paid speech API, backend audio uploads, or ChatGPT connection. Unsupported browsers keep typing available; iPhone Safari microphone/speech access must be tested on the user's device.

Type/Speak controls retain the same in-memory draft, hints and attempts. Each recording replaces the answer with an undo path; grading remains an explicit action after transcript review. Recognition supplies spelling and accents, so history records optional `inputMode` (typed/voice/mixed), `spellingIndependent`, `modelHeard`, and `guided` fields. Hearing a model before checking counts as support. The existing storage key, schema, exercise IDs and shared review schedule remain unchanged; this is exercise recall, not separate written/oral mastery.

Guided practice uses six existing translation exercises in three authored tense pairs (cocinar imperfect/preterite, escribir present/future, visitar preterite/perfect). It reads the task on entry/next, a clue after an unsuccessful answer, and the model after completion. Listening always starts with a user tap, never while playback is running. Leaving a screen, switching input, or hiding the page stops audio and recognition. This is a guided drill, not an open-ended AI conversation. Standard sessions can also enable guided audio. No active session or microphone state is persisted across reloads.

Run `npm run check` for course, grading, hint and recognition lifecycle tests. Browser QA covers draft/hint preservation, typed repairs and permission-denied fallback. Actual device recognition quality and speech playback require iPhone/Ubuntu testing.

### Responsive phone layout (v1.2.1)

At viewport widths up to 700 CSS pixels, the same app switches to a phone layout using CSS media queries. Main instructions use 17px text, answers 20px, and buttons generally have 48px touch targets. Input fields stay above the iOS focus-zoom threshold. The active practice view hides dashboard statistics to prioritise the current exercise. Navigation, accent keys and action buttons wrap without horizontal page scrolling; wide data tables retain their own scroll area. Safe-area spacing and pinch-to-zoom are preserved. Large-text preferences still increase exercise text further.

Voice instructions are condensed with expandable help/privacy details, and Stop audio only appears during playback. Phone-width browser QA checked exercise layouts at 320/390px frames, settings and lessons without horizontal overflow. Actual iPhone rendering remains a device-level check.

### Quick reference during practice (v1.3)

Every active exercise includes a collapsible Quick reference above the answer field. It shares the authored tense rules/endings from the lesson data and offers the current verb's authored conjugations where available. Changing reference tense never changes the exercise or draft. Tense-choice exercises initially ask the learner to select a reference tense rather than disclosing the correct target. Custom tenses without reference forms show their rule or teacher-notes fallback.

The browser preference `settings.practiceReferenceOpen` remembers whether to keep the panel open. Opening it while answering marks the attempt as supported; closing it later does not erase that support. The existing optional history fields gain `referenceUsed`. Following exercises default to their own tense, and existing storage IDs/schema remain stable. Browser QA verified phone fit, preserved drafts on tense changes and Type/Speak switches, supported grading and open-state retention on the next exercise.

### Answer keyboard assistance (v1.3.1)

The shared practice textarea explicitly uses `autocorrect="off"`, `spellcheck="false"`, `autocomplete="off"`, `autocapitalize="none"`, and `writingsuggestions="false"`, retaining `lang="es"`. This requests unassisted typing from supporting browsers. Device keyboards may still show their own suggestion strip or apply user-defined text replacements; Frase cannot change system keyboard settings. Apple Keyboard Settings can disable Predictive Text if needed. Typing, voice transcripts and Spanish character buttons continue to use the same textarea.

### Learning path and gentle gamification (v1.4)

The Quests tab provides 12 units, 37 quests and 403 curated exercises from A1 through B2 and introductory C1-oriented sentence skills. Each quest has six introductory checked exercises and one optional self-reviewed personal sentence. Eight foundation quests now have 24 checked examples each, including a separate six-prompt challenge set. Varied rounds balance due review, supported attempts and unseen examples in six checked prompts plus the optional personal task. Existing introduction and checkpoint IDs stay unchanged; separate bank coverage avoids presenting introductory completion as fluency. This selected path is guided by Cervantes PCIC inventories and CEFR communicative functions; it is not a complete syllabus or proficiency assessment. Practice retains its original five tense filters and 1,042 prompts. The original quest IDs and progress remain compatible.

The weekly practice-day goal rewards consistency without a fragile streak. Quest milestones distinguish supported completion, checkpoint answers without help and checkpoint recall after at least 24 hours. History and exercise IDs remain stable. See [curriculum authoring guide](docs/curriculum-guide.md) for the content model, review process, exact achievement definitions and extension instructions. Run `node scripts/check-curriculum.mjs` before publishing authored changes.

### Separate Practice and Quests tabs (v1.4.1)

Practice is the default landing view again and retains daily mix, tense filtering, production and voice drills. Quest cards are selected in the Quests tab and excluded from Practice sessions and its due count. Navigation supports `#quests` directly. Each study tab keeps its own in-memory session, draft, help state and input mode when switching tabs or visiting lessons/settings/progress. These transient sessions are not saved across page reloads; completed progress still uses the existing shared browser history and backup schema.


## Contextual paper practice (v1.7)

Practice and quest sessions expose Paper practice / PDF. Quest cards also open PDF for this quest. The modal defaults to the current tense or quest and preserves study drafts. Four contexts cover person/form conjugation, sentence production, preterite/imperfect meaning choice, and supported/due review. Conjugation prompts use stored five-person tables; ending-only support is applied only when the stored form exactly matches an explicit regular rule. Unsupported/irregular and compound forms request the whole form.

`dist/js/paper.js` creates deterministic worksheet manifests from reviewed content and the local notebook. Fresh sheets favour less-exported IDs; normal quest sheets keep the reserved challenge bank separate. Personal production ends every sheet. If a narrow selection has fewer distinct items than requested, the sheet is shorter with an explanation. Empty review selections show a useful message. Building/exporting never records attempts, completion, weekly activity, or SRS changes.

`dist/js/paper-pdf.js` writes an actual browser-local PDF 1.4 with standard Helvetica/WinAnsi fonts and Spanish accents, measured wrapping, handwriting space, US Letter/A4, and optional separately paginated answer keys. No remote PDF, AI, OCR or speech service is used. A download link and an open-for-print link support desktop and mobile workflows. Recent 30 complete manifests (not handwritten answers) are retained in the notebook as `paperSheets`, included in backup export, and allow downloading the same version again. Browser storage and backup limits still apply. Non-Western glyphs outside WinAnsi are not supported by the PDF font; worksheet prompts should use Spanish/English text.


### Focused conjugation recall (v1.9)

Practice → Focused keeps a persistent six-form set for each of the five core tenses. Start with worked examples and stem cues; subsequent rounds remove automatic cues and rotate sentence contexts. Typing, speech, graduated hints and quick reference share the ordinary exercise controls. Switching to another Practice mode pauses the Focused round for this visit.

The set covers all five subject groups with at most two forms per verb. Recent supported attempts on related regular endings help prioritise the next set. Checked course forms supply the answer keys; a small maintained complement bank supplies context variations. To extend this mode, add a reviewed verb context in `dist/js/focus.js` alongside a complete course conjugation table and its stable `form-<tense>-<verb>-<person>` cards.

Focused records and sets travel with the existing notebook backup. Old backups receive empty Focused state without changing existing history. The ordinary practice scheduler and quest milestones retain their existing rules. Later-day checks require an unaided first match at least 24 hours after support or the last credited later-day check on that target; same-day repeats do not advance the count or postpone its due date. Support resets that target's count. Two later-day successes enable an optional next set; this is not a claim of fluency. Voice recognition supplies spelling and accents.

A round starts with 12 prompts. A supported recall or revealed model can add one extra retry per target after at least three intervening prompts; occasional bridge prompts preserve that gap. These retries are bounded, so a difficult round always ends.

The design draws on [Kim & Webb (2022), spaced L2 practice](https://doi.org/10.1111/lang.12479), [Serfaty & Serrano (2024), grammar relearning](https://doi.org/10.1111/lang.12585), and [Pan et al. (2019), structured study and mixed conjugation practice](https://doi.org/10.1016/j.jarmac.2019.07.004). Six targets, 12 initial prompts and the review intervals are product choices rather than research-established optima.

## Watch & Understand (v1.10)

The **Watch** tab (`#watch`) adds nine curated Spanish After Hours videos across visual/repetition, everyday scenes and stories/stretch. Recommendations use the learner's optional **Easy / Mostly followed / Lost** feedback, not a CEFR assessment. Full videos are offered without forced quizzes or invented transcript segments. The shelf is based on verified creator titles/descriptions; exact audiovisual content, captions and timestamps have not been reviewed as lessons.

The YouTube privacy-enhanced player loads only after **Load video** is pressed. An **Open on YouTube** link remains available if embedding fails. Loading connects to YouTube; captions, speed controls and playback availability are controlled by YouTube. No video content, captions, paid exercises or transcripts are copied. The creator uses Spain-based Spanish, offering variety alongside Frase's Latin American course.

Watched marks, understanding ratings, the selected video and optional short phrase/scene notes are saved under `state.watch` within the existing `frase.learning.v1` notebook. Old backups receive an empty watch section. New backups include it automatically. This self-reported listening record does not change exercise records, spaced review, Focused targets, streaks or mastery. Watched marks and ratings can be undone. Opening a video never marks it completed. The player is left intact when saving ratings or notes; navigation away unloads it.

Source metadata is in `dist/js/watch-catalog.js`; pure progress/recommendation logic is in `watch.js`; the view is `watch-ui.js`. `tests/watch.test.mjs` covers migration, round trips, separation from mastery, recommendations, data validation, escaped rendering and route integration.
